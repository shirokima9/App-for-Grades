# درجاتي — تطبيق إدارة درجات الطلاب

تطبيق ويب (PWA) لإدارة درجات الطلاب يعمل **محليًا بالكامل** على جهازك — بلا سحابة، بلا إنترنت، بلا أي إرسال بيانات لأي جهة.

## المتطلبات

- Node.js إصدار 18 أو أحدث (يُثبَّت مرة واحدة).
- التثبيت الأول يحتاج إنترنت لتنزيل الحزم؛ بعدها يعمل التطبيق والجهاز غير متصل تمامًا.

## التشغيل

```bash
npm install        # مرة واحدة فقط
npm start          # يبني الواجهة ويشغّل الخادم ويطبع الرابط ورمز QR
```

## الوصول من الجوال

1. شغّل نقطة اتصال من جوالك ووصّل اللابتوب بها (أو اجعلهما على نفس شبكة Wi-Fi).
2. شغّل `npm start` — ستظهر روابط **كل** الشبكات المتاحة مع رمز QR لكل منها، مثل `http://192.168.x.x:4750`.
3. امسح الرمز بكاميرا الجوال وافتح الرابط.
4. من قائمة المتصفح اختر **"إضافة إلى الشاشة الرئيسية"** ليعمل كتطبيق مستقل.

## الشاشات

| الشاشة | الغرض |
|---|---|
| **الرصد** | رصد الدرجات أثناء الحصة: لوحة أرقام داخل التطبيق، حفظ فوري، انتقال تلقائي، تراجع |
| **السلوك** | تسجيل المخالفات بالحدث + شاشة التكرار + الوسوم الجاهزة |
| **الحضور** | حضور سريع بنقرة + تقرير غياب تراكمي |
| **التحليل** | التوزيع، المقارنات، المتوسط والوسيط والانحراف، المتعثرون، ربط الدرجة بالسلوك |
| **التقارير** | تقرير ولي الأمر + نص واتساب + تصدير PDF |
| **التسليم** | تصدير نسختك + الكتابة في نسخة من الملف الوزاري مع المعاينة والتحقق |
| **استيراد** | استيراد الملف الوزاري: تشخيص، مسح بنيوي، مطابقة أعمدة، مطابقة أسماء |

## رصد الدرجات من الجوال

- اختر الشعبة ثم عنصر التقييم، وستظهر قائمة الطلاب.
- **لوحة أرقام داخل التطبيق** (لا لوحة مفاتيح النظام) بأزرار كبيرة.
- **حفظ فوري** بعد كل درجة — لا يوجد زر حفظ ختامي.
- **انتقال تلقائي** للطالب التالي بعد الإدخال.
- الطلاب غير المرصودين مميزون بخط جانبي وشارة "غير مرصودين".
- زر **تراجع** يعيد آخر إدخال لقيمته السابقة.

## العمل دون اتصال

كل إدخال (درجة / مخالفة / حضور) يُحفظ في **IndexedDB** داخل المتصفح ثم يُرسل فورًا. إن انقطع الاتصال، تُصطف العمليات وتُرسَل تلقائيًا عند عودته. مؤشر الحالة في أعلى الشاشة يعرض: **متزامن** / **بانتظار المزامنة (العدد)** / **غير متصل** — واضغط عليه للمزامنة الفورية. كل عملية تحمل معرّفًا فريدًا يمنع التكرار عند إعادة الإرسال.

## استيراد الملف الوزاري

1. من الشاشة الرئيسية أنشئ الشعبة (الصف + اسم الشعبة).
2. افتح **استيراد** واختر ملف الإكسل الوزاري.
   - **الملف الأصلي يُقرأ فقط ولا يُكتب فيه أبدًا.**
3. راجع **التشخيص** أولًا: أسماء الأوراق، الخلايا المدمجة ومواقعها، الصفوف والأعمدة المستخدمة فعليًا، وأول 10 صفوف كما هي خامًا — ترى ما يراه التطبيق قبل أي قرار.
4. راجع **تقرير المسح البنيوي**: صف العناوين المكتشف، الأعمدة (قيم أم معادلات)، قواعد التحقق، ونطاق صفوف الطلاب.
   - إن لم يكتشف التطبيق صف العناوين **بثقة** فلن يخمّن: سيتوقف ويطلب منك تحديده يدويًا ثم إعادة التحليل.
5. طابق الأعمدة يدويًا (اسم الطالب، أعمدة الدرجات...) وتُحفظ **كقالب** حتى لا تكرر المطابقة.
6. راجع **تقرير مطابقة الأسماء**:
   - تطابق تام: يُقبل تلقائيًا.
   - تطابق قريب: لن يُقبل أبدًا دون تأكيدك يدويًا.
   - بدون تطابق: تقرر أنت (طالب جديد أو تخطي).
   - **لا يمكن تثبيت الاستيراد وهناك حالة واحدة غير محسومة.**
7. عند إعادة استيراد ملف محدَّث يظهر تقرير فروقات: من أُضيف، من حُذف، من انتقل.
   - بجانب كل طالب مفقود زر **أرشفة**: تُخفيه من القوائم فقط — درجاته وملاحظاته تبقى محفوظة ويمكن **استرجاعه** من صفحة الطلاب في أي وقت.
   - الطالب المنقول بين الشعب تنتقل معه كل درجاته وملاحظاته.

### التطبيع في مطابقة الأسماء

يُطبَّع الاسم داخليًا للمقارنة فقط (الاسم الأصلي يبقى كما هو للعرض والتصدير):
توحيد الهمزات (أ/إ/آ ← ا)، التاء المربوطة ← هاء، الألف المقصورة ← ياء، حذف التشكيل والتطويل، توحيد المسافات، وإزالة **المسافات غير القابلة للكسر وعلامات الاتجاه المخفية** (RLM/LRM/ALM والأحرف صفرية العرض وBOM) الشائعة في الملفات العربية المنسّقة.

## الكتابة في الملف الوزاري — أخطر عملية

### كيف تُحفظ بنية الملف؟

ملف `.xlsx` أرشيف ZIP من ملفات XML. التطبيق يعدّل **فقط** عناصر الخلايا المستهدفة داخل XML الورقة، وكل ملف آخر في الأرشيف يُنقل كما هو. لذلك تبقى المعادلات والحماية وقواعد التحقق والتنسيقات الشرطية والخلايا المدمجة سليمة تمامًا.

### القيم المخزّنة للمعادلات

خلية المعادلة في xlsx تحتوي المعادلة `<f>` **وقيمة محسوبة مخزّنة** `<v>`. لو غُيّرت خلية إدخال دون معالجة هذا، تبقى المجاميع تعرض القيم القديمة الخاطئة. لذلك التطبيق:

1. يحذف القيمة المخزّنة `<v>` من كل خلايا المعادلات في الورقة (المعادلة نفسها تبقى كما هي حرفيًا).
2. يضبط `fullCalcOnLoad="1"` في `workbook.xml` — إعادة حساب إجبارية عند فتح الملف.
3. يحذف `xl/calcChain.xml` (ذاكرة الحساب القديمة) ومرجعه من `[Content_Types].xml`.

### القواعد الإلزامية المطبَّقة

- **كل تسليم يبدأ من الأصل النظيف**: تُنسخ نسخة جديدة من الملف الأصلي وتُكتب فيها كل الدرجات المتراكمة دفعة واحدة. الكتابة فوق نسخة سبق أن كُتب فيها **مرفوضة برمجيًا**.
- لا كتابة إلا في خلايا الدرجات المحددة في التخطيط — ولا في خلية معادلة (فحص مزدوج: من التخطيط ومن XML نفسه).
- لا كتابة خارج نطاق صفوف الطلاب المحدد.
- **فحص قيود Data Validation قبل الكتابة**: أي درجة خارج المدى توقف العملية كاملة.
- **طالب واحد غير مثبَّت المطابقة يوقف العملية كلها.**
- لا يُعاد ترتيب الصفوف إطلاقًا — كل درجة تُكتب في صف الطالب كما هو في الملف الأصلي.
- **معاينة إلزامية (Dry Run)** بجدول لكل طالب (اسمي / الاسم الوزاري / الخلية / القيمة / الحالة) وملخص أعلاه، ولا كتابة قبل زر تأكيد صريح.
- **تقرير تحقق بعد الكتابة**: يُعاد فتح الملف الناتج وتُقارن كل قيمة بقاعدة البيانات، وتُقارن أعداد المعادلات وقواعد التحقق والحماية والدمج والتنسيق الشرطي قبل/بعد، ويُتحقق أن لا ملف فُقد من الأرشيف.

### ✅ التحقق اليدوي — مرة واحدة قبل أن تثق بالأداة

بعد أول عملية تسليم ناجحة، افتح الملف الناتج من مجلد `submissions/` في **إكسل** وتأكد بنفسك من أربعة أشياء:

1. **تحدّث المجاميع**: انظر إلى عمود «المجموع» — يجب أن يساوي مجموع الدرجات الأربع المكتوبة في نفس الصف، لا قيمة قديمة ولا صفرًا. (جرّب: غيّر درجة في خلية إدخال يدويًا وسترى المجموع يتغير فورًا.)
   - إن ظهر المجموع فارغًا أو صفرًا عند الفتح: اضغط `Ctrl+Alt+F9` لفرض إعادة الحساب. إن لم يتغير، أخبرني — فهذه مشكلة حقيقية يجب حلها.
2. **قوائم التحقق باقية**: اضغط على خلية في عمود «الحالة» — يجب أن تظهر القائمة المنسدلة (مستمر / منقول / منسحب).
3. **مدى الدرجات محفوظ**: اكتب `99` في خلية درجة — يجب أن يرفضها إكسل برسالة «الدرجة يجب أن تكون عددًا صحيحًا بين 0 و 20».
4. **حماية الورقة باقية**: جرّب الكتابة في خلية «المجموع» — يجب أن يرفض إكسل التعديل لأن الورقة محمية.

> **ملاحظة صريحة**: تم التحقق من هذه النقاط الأربع على مستوى بنية XML بالاختبارات الآلية (14 اختبارًا)، لكن **لم يتم فتح الملف في إكسل أو ليبر أوفيس فعليًا** أثناء التطوير لأن ليبر أوفيس غير صالح في بيئة التطوير. لذلك تحققك اليدوي مرة واحدة هو التأكيد النهائي.

## نسختي الخاصة (exports/)

ملف `.xlsx` جديد تمامًا لا علاقة له بالملف الوزاري، يحتوي:
- كل عناصر التقييم والمجموع.
- عمود **السلوك** (عدد المخالفات) وعمود **الكتاب** (عدد مرات عدم إحضار الكتاب).
- عمود **الملاحظات** يجمع الملاحظات مع تواريخها ووسومها.
- أعمدة الغياب والتأخر.
- الأسماء مرتبة **أبجديًا ترتيبًا عربيًا صحيحًا** (عبر `Intl.Collator('ar')`) — وهذا الترتيب **لا يُطبَّق أبدًا** على الملف الوزاري.
- اسم الملف يتضمن الشعبة والتاريخ.

## تقارير أولياء الأمور

- تقرير لطالب واحد يجمع الدرجات ونسبة الحضور والمخالفات بتواريخها وملاحظاتها.
- **نص رسالة عربية مهذبة** جاهز مع زر نسخ للإرسال عبر واتساب.
- **تصدير PDF**: الزر يفتح نافذة الطباعة — اختر «حفظ كـ PDF».
  > اخترنا الطباعة من المتصفح بدل توليد PDF في الخادم لأنها الطريقة الوحيدة التي تضمن **تشكيل الحروف العربية واتجاه RTL بشكل صحيح 100%**، وبالخط العربي المضمَّن محليًا في التطبيق. مكتبات PDF في Node لا تتعامل مع البيدي العربي بشكل موثوق.
- **تقارير الشعبة كاملة** دفعة واحدة، كل طالب في صفحة مستقلة عند الطباعة.

## أين تُحفظ بياناتي؟

كل شيء داخل مجلد المشروع فقط — لا شيء يغادر جهازك:

| المجلد | المحتوى |
|---|---|
| `data/school.db` | قاعدة البيانات (الطلاب، الدرجات، الملاحظات، الحضور، القوالب) |
| `data/uploads/` | نسخ للقراءة من الملفات الوزارية المستوردة (تُستخدم كأصل نظيف عند كل تسليم) |
| `backups/` | نسخ احتياطية تلقائية قبل كل استيراد وكل عملية كتابة |
| `exports/` | نسخ العمل الخاصة بك |
| `submissions/` | نسخ التسليم الوزارية المكتوبة |

## استرجاع نسخة احتياطية

النسخ في `backups/` باسم يتضمن التاريخ والسبب، مثل `school-2026-09-09T11-28-30-import.db`:

```bash
# أوقف التطبيق أولًا (Ctrl+C) ثم:
cp backups/school-<التاريخ>-<السبب>.db data/school.db
npm start
```

سجل العمليات (audit log) داخل التطبيق يوثّق كل عملية كتابة: متى، أي ملف، كم خلية، ونتيجة تقرير التحقق.

## الاختبار

```bash
npm test              # 14 اختبار وحدة (التطبيع، المطابقة، محرك الكتابة)
npm run make:sample   # ينشئ samples/ministry_sample.xlsx
node scripts/e2e-test.mjs   # دورة كاملة (شغّل الخادم أولًا)
```

الملف التجريبي يحاكي ملفًا وزاريًا حقيقيًا: ترويسة مدرسة علوية وصف فارغ (صف العناوين هو الخامس)، معادلات مجموع وتقدير **مع قيم محسوبة مخزّنة كما يحفظها إكسل**، تحقق من صحة البيانات (0–20)، قائمة منسدلة، تنسيق شرطي، ورقتان محميتان بكلمة مرور، و25 طالبًا بأسماء رباعية بعضها متقارب عمدًا (أحمد سالم/أحمد سليم، عبدالله/عبد الله، محمد/محمود).

## الخصوصية

- لا CDN، لا خطوط من الإنترنت، لا تحليلات، لا أي استدعاء API خارجي.
- الخط العربي (Cairo) وReact وRecharts وكل المكتبات مضمَّنة داخل المشروع.
- بيانات الطلاب أمانة رسمية — لا تغادر جهازك إطلاقًا.
